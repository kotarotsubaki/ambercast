## 互換性ポリシー {#compatibility-policy}

アーティファクトのバージョン受け入れは、リリース番号の直感ではなく、[Ambercast 計画仕様](/ambercast/ja/spec/overview/#compatibility)に従わなければならない（MUST）。計画は派生アーティファクトであるため、スキーマバージョンの変更はマイナーリリースでの再生成を要求してもよい（MAY）（`repo:src/core/ir/schema.ts:46-62`）。

## 設計根拠 {#rationale}

変更履歴は、互換性の変更とその再生成の帰結を1つの規範的な場所に記録する。そのため、コンシューマーはパッケージのバージョンからアーティファクトの互換性を推論しなくてよい。

却下した代替案は、パッケージのリリースだけを追跡するものだった。プロデューサー契約のフィンガープリントが変わると、計画のスキーマバージョンが同じでも計画が stale になりうるため、この案は却下した（`repo:CHANGELOG.md:219`、`repo:src/core/ir/schema.ts:46-62`）。
