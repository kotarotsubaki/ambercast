import { Steps, LinkCard } from '@astrojs/starlight/components';

列出所有变更文件，依次审查 Prompt、执行计划和定位缓存，最后运行 `check`。

## 前置条件 \{#prerequisites}

解析器通过固定后缀，把 Prompt 对应到它的执行计划和定位缓存伴生文件：`<name>.ambercast.plan.json` 与 `<name>.ambercast.grounding.json`。

## 操作步骤 \{#steps}

<Steps>

1. ## 列出变更的文件 \{#list-changes}

   ```bash
   git status --short
   ```

   对每个未跟踪的 Prompt、执行计划或定位缓存路径，检查其完整内容，或运行 `git diff --no-index /dev/null <path>`。对已跟踪且发生变更的文件，运行 `git diff -- <path>`；文件已暂存时，运行 `git diff HEAD -- <path>`。这样在审查含义之前，就能确定完整的候选文件集。

2. ## 审查 Prompt \{#review-prompt}

   阅读 `tests/ambercast/<name>.test.md`，说明预期的用户结果。Prompt 规范化只会改变开头的一个 BOM 和换行符的表示。

3. ## 审查执行计划 \{#review-plan}

   阅读 `tests/ambercast/<name>.ambercast.plan.json`，把生成的步骤与该结果比对。执行计划是单独的派生伴生文件。

4. ## 审查定位缓存 \{#review-grounding}

   阅读 `tests/ambercast/<name>.ambercast.grounding.json`，区分解析变化与意图变化。定位缓存也是单独的派生伴生文件。当 `grounding.repositoryPolicy` 为 `uncommitted` 时，可能没有定位缓存文件，此时跳过这一步。

5. ## 检查新鲜度 \{#check-freshness}

   ```bash
   npx ambercast check tests/ambercast/<name>.test.md
   ```

   `check` 不具备写入、浏览器或提供商能力。

</Steps>

## 验证 \{#verification}

只有被接受的这一对文件为 fresh 时，`check` 的退出码才为 `0`。在 `uncommitted` 策略下没有定位缓存文件时，它会报告 `fresh-without-grounding`，退出码同样为 `0`。
